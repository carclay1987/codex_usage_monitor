# Дашборд расхода Codex

Локальный дашборд читает журналы задач и базы состояния из `~/.codex` и показывает:

- активные и недавние задачи;
- накопительный расход токенов и расход последнего хода;
- заполнение контекстного окна;
- долю кэшированных входных токенов, вход, выход и reasoning-токены;
- историю роста контекста с подсказками, периодами, масштабом и точными метками сжатий;
- оценку стартового пакета, расход по типам действий и объём ответов инструментов;
- сигнал о переходе в новую задачу после повторных сжатий;
- общий недельный лимит Codex и оценку вклада каждой задачи;
- модель, reasoning и разбивку токенов всех сабагентов в дереве задачи;
- боковую панель с недавними задачами и группировкой по проектам, поиск и сортировку.
- настройки каталога Codex, частоты обновления и глубины анализа;
- фоновый AI-аудит агрегированной статистики через уже авторизованный Codex.

## Запуск

Требования: macOS или Linux, Node.js 22.13 или новее и npm 11.16.0. Установленный Codex или
ChatGPT нужен только для AI-аудита; просмотр локальной статистики работает без
обращения к модели.

```bash
git clone git@github.com:carclay1987/codex_usage_monitor.git
cd codex_usage_monitor
npm ci
npm run dashboard
```

После запуска открыть <http://localhost:3000/>. Интерфейс обновляется каждые 2,5 секунды.

Служба данных доступна только локально на `127.0.0.1:64111`. Каталог Codex и параметры чтения можно изменить через шестерёнку; настройки сохраняются в `~/.codex-usage-monitor/settings.json`. Начальное значение каталога можно передать через `CODEX_DATA_DIR`, другой порт — через `CODEX_USAGE_PORT`.

Кнопка «AI-аудит расхода» открывает последний сохранённый результат и сама по
себе не расходует лимит. Кнопка «Запустить новый аудит» внутри окна строит
локальный агрегированный отчёт без текста сообщений и содержимого ответов
инструментов, затем запускает `codex exec` из установленного приложения в режиме
только чтения. Дополнительный вход не требуется, если Codex уже авторизован через
ChatGPT. Результат и использованный отчёт сохраняются в
`~/.codex-usage-monitor/audit/`, поэтому их можно открыть после перезапуска.

## Как считается контекст

Процент контекста равен `last_token_usage.input_tokens / model_context_window × 100`. Это заполнение входного окна модели на последнем ходе, включая кэшированную часть истории. Показатель не равен доле недельного лимита подписки.

Накопительные токены отражают объём обработки, но не позволяют точно восстановить
вклад конкретной задачи в лимит подписки: сервер Codex сообщает общий процент
лимита без разбивки по задачам. Дашборд оценивает вклад по моментам роста общего
счётчика. Из-за округления и параллельных задач эта оценка не является биллингом.

## Приложение для macOS

Готовый установщик для Mac с Apple Silicon:

`release/Codex Usage Monitor-0.1.0-arm64.dmg`

Приложение автономно запускает локальную службу данных и читает `~/.codex`
текущего пользователя. После запуска оно остаётся в строке меню macOS: рядом с
иконкой показан расход недельного лимита, а при наведении — остаток, время сброса
и активные задачи. Клик по иконке открывает компактную панель с недельным
лимитом и тремя последними чатами; полный dashboard открывается из панели или
контекстного меню.
Журналы не отправляются наружу, вход в аккаунт и API-ключ не нужны. Веб-версию
можно запускать одновременно: она подключится к уже работающей службе приложения.

Текущая сборка не подписана Developer ID и не нотариализована Apple. При первом запуске macOS может потребовать открыть приложение через контекстное меню Finder → «Открыть». Для публичного распространения без этого предупреждения нужны сертификат разработчика и нотариализация.

Команды разработки и сборки:

```bash
npm ci
npm run desktop:dev
npm run desktop:pack
npm run desktop:dmg
```

`npm run desktop:pack` создаёт приложение в `release/mac-arm64/`, а
`npm run desktop:dmg` — установщик
`release/Codex Usage Monitor-0.1.0-arm64.dmg`. Текущая конфигурация собирает
версию для Mac с Apple Silicon.

## Приложение для Linux

Linux-приложение собирается в формате AppImage для архитектуры текущей системы:

```bash
npm ci
npm run desktop:linux
```

Готовый файл появится в `release/`, например
`release/Codex-Usage-Monitor-0.1.0-x86_64.AppImage`. После запуска открывается
dashboard и создаётся значок в системном трее. Закрытие окна скрывает его, но
приложение продолжает собирать и показывать статистику. Dashboard можно снова
открыть через меню значка; пункт «Выйти» полностью завершает приложение.

Если AppImage нельзя запустить напрямую, выдайте ему право на выполнение:

```bash
chmod +x release/Codex-Usage-Monitor-*.AppImage
```
